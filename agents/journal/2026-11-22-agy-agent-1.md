## What changed

- The cache: a generic remote `antigravity` for `storage.googleapis.com/antigravity-public`, where Google's
  manifest points the CLI's archives, 10 GB cap (`apps/homeserver/artifact-keeper/remotes.txt`).
- `ansible/agent.yml`: gnome-keyring and libsecret-tools, and an unencrypted `login` keyring as the default
  for `aman`. `agy` stores its sign-in in the Secret Service and a headless VM has no login to unlock one.
  `files/agent/agy-update.sh` as `/usr/local/sbin/agy-update` installed agy 1.5.14 in `/usr/local/bin` and
  runs daily from `agy-update.timer`. agy's own updater is off (`AGY_CLI_DISABLE_AUTO_UPDATE`) in the
  owner's shell and in the Orca server's service, which restarted once for it.

## Snapshot / backup taken

None: new packages, files and a timer only, and the cache's new remote holds only cached files

## How it was verified

- `cache-remotes.sh`: `antigravity: created (200)`, cap 10 GB. The 101 MB archive fetched through it on
  agent-1 matched the manifest's SHA-512, and a second fetch took 0.45 s.
- By hand first, with gnome-keyring: a secret stored with `secret-tool` read back, also after a restart of
  the daemon, then removed. The unencrypted keyring file was the only setup that worked headless; unlocking
  a password keyring from stdin left no `login` collection.
- `--check --diff`, then a run (7 changed) and a second run (0 changed). `agy --version` is 1.5.14,
  `orca agent installed` on agent-1 lists `antigravity`, and `agy-update` reports 1.5.14 as the latest.
