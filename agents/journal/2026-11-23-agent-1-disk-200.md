# 2026-11-23 — Grow agent-1's root disk to 200 GB

**Who:** Claude Code, at the owner's request. **Scope:** `agent-1`. **Mode:** write.
**Task:** Grow the root disk by about 50 GB, from 150 GB to 200 GB. **Skill:** none.

## What changed

- The owner chose to shut down at once, knowing it would end a Claude session, Hermes and the Orca daemon running on the VM.
- Through the Xen Orchestra REST API: a clean shutdown, a `PATCH` of the root disk's `size` to 200,001,191,936 bytes (95,368 whole 2 MiB blocks), and a start. The VM was down for about two minutes.
- Updated `iac/agent-vm.tf` to the new size. The resize went through the API instead of `tofu apply` for the reason in `agents/journal/2026-11-23-agent-1-resize.md`: a VM update from the provider can reset the 10 GiB static memory maximum.
- Before the change, the `Nvme` storage repository reported 983 GB in size and 756 GB physically used (REST API, `srs`). The disk is thin, so the extra 50 GB takes space only as it fills.

## Snapshot / backup taken

Xen Orchestra snapshot `agent-1 before disk resize to 200 GB 2026-11-23`. The API returned `201` and listed it before the shutdown. The earlier snapshot `agent-1 before RAM and disk resize 2026-11-23` is still there; neither has been removed.

## How it was verified

- After the start, Xen Orchestra reported the VM running, the disk at 200,001,191,936 bytes, and memory unchanged: dynamic 256 MiB to 8 GiB, static maximum 10 GiB.
- Over SSH: `lsblk` showed `xvda` at 200,001,191,936 bytes; the boot journal showed `systemd-growfs-root` resized `/` to 186.1G; `df -h /` reported 184G total and 120G available; `systemctl is-system-running` reported `running` with no failed units; the Hermes gateway and the Orca daemon were running again.
- With the config at 200 GB, `./run.sh plan` reported no changes.
